# Motion Meme MVP Email Notification Plan

## 목적

이 문서는 MVP에서 Resend 기반으로 보낼 이메일 이벤트를 확정하고, 구현 순서와 운영 기준을 정리하기 위한 문서다.

## MVP 이메일 범위

이번 MVP에서 보내는 이메일은 아래 4개로 제한한다.

1. 새 DM 수신
2. 내 게시물에 새 댓글
3. 업로드 안 한 성공 플레이 1회 리마인드
4. 주간 요약

## 이벤트별 발송 기준

### 1. 새 DM 수신

- 발송 조건:
  - 사용자가 앱 밖에 있을 가능성이 높은 상태에서 새 DM이 도착
  - 같은 대화방에서 너무 자주 반복 발송하지 않도록 쿨다운 필요
- 권장 중복 방지:
  - `new-dm/{conversation_id}/{message_id}`
- 메일 목적:
  - 사용자를 다시 room으로 복귀시키기

### 2. 내 게시물에 새 댓글

- 발송 조건:
  - 다른 사용자가 내 게시물에 댓글 작성
  - 내 자신의 댓글은 제외
- 권장 중복 방지:
  - `new-comment/{comment_id}`
- 메일 목적:
  - 댓글 스레드 재방문 유도

### 3. 업로드 안 한 성공 플레이 1회 리마인드

- 발송 조건:
  - 성공 플레이 세션이 생성됐지만 업로드 안 됨
  - 일정 시간 이후에도 `uploaded_at is null`
  - 세션당 1회만 발송
- 권장 중복 방지:
  - `unpublished-run-reminder/{play_session_id}`
- 메일 목적:
  - 업로드 전환율 회복

### 4. 주간 요약

- 발송 조건:
  - 최근 7일 내 활동이 있거나, 반응/신규 메시지/신규 업로드가 있는 사용자
  - 주 1회 고정
- 권장 중복 방지:
  - `weekly-digest/{user_id}/{yyyy-week}`
- 메일 목적:
  - 재방문 유도 + 성과 회고

## Resend 구현 기준

- Next.js 서버 측에서 Resend Node SDK 사용
- React Email 또는 React 기반 템플릿 사용
- 모든 발송은 idempotency key 적용
- 가능하면 발송 이벤트와 상태를 DB에 기록

## 사용자가 해야 할 준비

1. Resend 계정 생성
2. 발신 도메인 인증
3. API 키 발급
4. 아래 env 값 준비
   - `RESEND_API_KEY`
   - `RESEND_FROM_EMAIL`
5. 발송자 이름/도메인 포맷 확정
6. 주간 요약을 보낼 기준 timezone 결정

## 구현 메모

- 새 DM / 새 댓글은 트랜잭션 알림 성격
- 업로드 리마인드 / 주간 요약은 재참여 유도 성격
- 이메일은 많이 보내는 것보다 “다시 앱으로 돌아오게 하는 순간”에만 보내는 게 MVP에 맞다
