# Motion Meme MVP Product Gap Plan

## 목적

이 문서는 현재 구현 상태와 PRD/TRD 기준 사이의 제품 갭을 5개의 큰 축으로 정리하고, 앞으로의 구현 우선순위를 명확히 하기 위한 실행 문서다.

기준:
- 기준 문서: `PRD.md`, `TRD.md`, `DELIVERY_PLAN.md`, `DB_SCHEMA.md`
- 기준 구현 상태: `docs/IMPLEMENTATION_STATUS.md`

## 현재 판단

현재 서비스는:
- 인증, DB, 공개 피드, 검색, 프로필, 글쓰기, `/play` 기본 루프까지는 연결되어 있음
- 그러나 PRD/TRD 기준의 “제품형 SNS + 플레이 MVP”로 보기에는 아직 큰 축 5개가 남아 있음

즉,
- 장난감 단계는 지났고
- 핵심 루프는 보이기 시작했지만
- 완성형 MVP로 가기 위한 제품 갭이 아직 명확히 존재함

## 앞으로 반드시 메워야 할 5개 축

### 1. 개인 채팅 / Realtime DM

#### 왜 필요한가

- 사용자가 영상/게시물을 보고 바로 대화할 수 있어야 SNS성이 살아난다.
- 사용자가 명시적으로 요구한 추가 범위다.
- 현재 구현에는 direct message, inbox, realtime subscription이 전혀 없다.

#### 현재 상태

- 1차 구현 완료
- `meme.conversations`, `meme.conversation_members`, `meme.messages` 반영
- participant 기반 RLS + `supabase_realtime` publication 반영
- `/messages` inbox / `/messages/[conversationId]` room / feed·profile DM CTA 반영

#### 필요한 구현

- 대화방(conversations) 모델
- 참여자(conversation_members) 모델
- 메시지(messages) 모델
- 읽음 상태(read state) 모델
- Realtime subscription
- inbox/list UI
- 1:1 채팅 화면
- 게시물/프로필에서 DM 진입 CTA

#### 완료 기준

- 팔로우 여부와 무관하게 프로필/게시물에서 DM 진입 가능
- 두 사용자 간 1:1 채팅방 생성 가능
- 메시지 전송/수신이 realtime으로 반영됨
- 최근 대화 목록과 unread 상태가 보임

---

### 2. 플레이 보조 흐름

#### 왜 필요한가

- PRD/TRD에는 카메라 권한 안내, 튜토리얼, 기록 화면이 명시돼 있다.
- 현재는 `/play` 안에 일부 UX가 섞여 있을 뿐, 온보딩/기록 흐름이 분리돼 있지 않다.

#### 현재 상태

- 1차 구현 완료
- `/camera` 권한 안내 / 재시도 UX 반영
- `/tutorial` 튜토리얼 / 가이드 반영
- `/history` 기록 / 히스토리 화면 반영

#### 필요한 구현

- 카메라 권한 안내 화면
- 권한 거부 재시도 UX
- 짧은 튜토리얼 스텝
- 기록/히스토리 페이지
- stage별 최고 점수 / 이전 영상 / 최근 플레이 목록 UI

#### 완료 기준

- 사용자가 `/play` 진입 전 권한/가이드를 이해할 수 있음
- 권한 거부 시 재시도 경로가 명확함
- 별도 기록 화면에서 이전 플레이와 영상 확인 가능

---

### 3. SNS 제품화

#### 왜 필요한가

- 현재는 feed, search, profile, comment가 연결돼 있지만 “제품형 SNS” 수준의 액션과 안전장치가 부족하다.
- 특히 타인 글 메뉴, 댓글 미디어, 신고/차단/저장 계열 기능이 빠져 있다.

#### 현재 상태

- 자기 글: 수정/삭제 가능
- 타인 글 more 메뉴: 1차 구현 완료
- 댓글 미디어: 1차 구현 완료
- 신고/차단/숨기기: 1차 구현 완료
- 저장(Saved Memes): 실제 `post_bookmarks` 모델 반영 완료

#### 필요한 구현

- 타인 글 more 메뉴
  - 링크 복사
  - 신고
  - 숨기기
  - 차단(최소 모델 포함 여부 검토)
- 댓글 미디어 2차 polish
  - 복수 이미지 여부
  - 모바일 clipboard 보강
  - 렌더링 디테일 정리
- 실제 saved/bookmark 모델
- 신고/차단 최소 모델

#### 완료 기준

- 타인 콘텐츠에 대한 기본 액션이 제공됨
- 댓글에 이미지/스크린샷 첨부 가능
- 저장/신고/차단 중 MVP 최소셋이 작동함

---

### 4. 프로필 고도화

#### 왜 필요한가

- PRD는 프로필에서 소개글, 대표 밈, 최근 영상, 최고 점수, 누적 플레이 수를 핵심 정보로 보게 한다.
- 현재는 일부 수치와 게시물 리스트는 있으나 “최근 영상/대표 밈”이 제품적으로 잘 드러나지 않는다.

#### 현재 상태

- bio / best score / total plays / posts는 있음
- recent video 강조 구조 1차 반영 완료
- featured meme / featured post 의미를 `featured_post_id` 우선 + 최근 업로드 fallback으로 정리

#### 필요한 구현

- 프로필 상단 recent video 섹션
- featured meme/featured post 의미 확정 및 UI 강화
- 업로드 완료 play 영상 중심 하이라이트
- 프로필 성과 요약 영역 고도화

#### 완료 기준

- 프로필 첫 화면에서 최근 영상과 대표 밈이 명확히 보임
- 플레이 성과와 SNS 정체성이 함께 드러남

---

### 5. 플레이 성공 경험 / 연출 완성도

#### 왜 필요한가

- PRD/TRD에서 가장 중요한 차별점은 강한 성공 연출, 밈 오버레이, 무대감이다.
- 현재 `/play`는 동작은 하지만 제품 차별점인 “터지는 성공 경험”은 아직 약하다.

#### 현재 상태

- 점수 계산 / preview / 업로드는 있음
- 성공 시 밈 오버레이/강한 연출은 부족
- 이번 턴은 `/play` 본체 직접 수정 대신 권한/튜토리얼/히스토리와 프로필/피드 쪽 성공 경험 보강을 우선 반영

#### 필요한 구현

- 성공/실패 피드백 강화
- 밈 오버레이 실제 시각 연출
- combo / flash / freeze frame 보강
- stage별 시각적 보상 강화

#### 완료 기준

- 사용자가 성공 순간을 즉시 인지할 수 있음
- 업로드하고 싶어지는 결과 화면이 만들어짐
- Motion Meme의 차별점이 플레이 경험에서 드러남

## 권장 우선순위

1. 개인 채팅 / Realtime DM
2. 플레이 보조 흐름
3. SNS 제품화
4. 프로필 고도화
5. 플레이 성공 경험 / 연출 완성도

## 작업 메모

- `/play`는 사용자와 함께 보며 수정 중이므로, 플레이 본체를 건드릴 때는 시각/UX 변경 의도를 명확히 구분해 진행해야 한다.
- build는 사용자가 명시적으로 요청하기 전까지 돌리지 않는다.
- 각 축은 문서 갱신과 구현을 같이 가져가야 한다.
- 댓글 이미지/스크린샷 저장은 1차 구현 완료 상태이며, 복수 이미지/모바일 clipboard polish가 남아 있다.
- 추천 feed는 이번 턴에 완성하지 않았고, 현재는 `popular = 반응 수 + 최근성 가중치`까지 반영된 상태다.
